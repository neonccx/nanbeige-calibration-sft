# Dataset card

## Active v3 extension

`dataset_v3/` contains 1,839 protocol `calibration-step-0.3` next-action examples over 40 virtual
devices: 1,032/175/182/450 train/validation/test/OOD. It adds a complex frequency × normalized-ZPA
S21 grid, periodic sweet-spot fitting, committed `z_bias`, bias-dependent spectroscopy and a synthetic
single-qubit XEB-style decay stage. There are 155 ZPA2D and 160 XEB native-call targets.

All 1,598 referenced acquisition artifacts are SHA-256 addressed. The audit validates rectangular
ZPA2D axes/grid shapes, device-level split isolation and absence of hidden SQUID/XEB truth from model
messages. `evaluator_only/` remains excluded from training. OOD includes drift, quasistatic noise,
very high receiver noise, shifted/long-period flux sweet spots and deliberately sub-threshold XEB.

The XEB stage is not multiqubit random-circuit-sampling XEB, a two-qubit benchmark or a coupler
calibration. It is a single-qubit synthetic exponential-decay proxy; standard Clifford randomized
benchmarking is generally more conventional for single-qubit gate characterization.

## Preserved v2 dataset

The active dataset is documented in [`dataset_v2/README.md`](dataset_v2/README.md) and
[`docs/DATASET_V2.md`](docs/DATASET_V2.md). It contains 2,705 next-action examples from 304
executed synthetic trajectories over 80 virtual devices:

| Split | Examples | Role |
| --- | ---: | --- |
| train | 1,670 | LoRA optimization only |
| validation | 280 | optimization diagnostics |
| test | 277 | frozen in-distribution evaluation |
| OOD | 478 | frozen stress profiles |

Complete device groups are isolated across splits. Public model messages contain controller state,
registered fit outputs and immutable raw-artifact references, but never simulator truth. The
`evaluator_only/` records are not training inputs.

The manifest's source hashes identify the generator-time Agent snapshot, while its split hashes
verify the released JSONL bytes. The separately released Agent has continued to evolve in its CLI,
evaluation harness and prompt profiles, so current runtime source hashes are not expected to match
every generator-time hash.

The simulator covers complex S21, spectroscopy, finite-pulse Rabi, signed Ramsey, T1, echo and
integrated dispersive IQ acquisition. It is a reduced two-level RWA/Markov/linear-cavity model, not
hardware data, an EM solver or a full digital twin. Selected regimes were independently checked with
QuTiP; those checks do not validate every synthetic prior or noise process.

The target is exactly one native `calibration.step` call selecting the next experiment and bounded
parameter action. Numerical fitting is performed by registered tools. Final success is decided by
the controller after two independent held-out IQ acquisitions pass the fixed F0, F1, visibility,
SNR and assignment-fidelity gates.

## Legacy v1.1 dataset

The top-level `dataset/` and `figures/` directories preserve the earlier 122-device question-answer
dataset. Its recommended train/validation/test counts are 5,001/591/604, grouped by `qubit_id`.
It repeats physical arrays across several question templates and uses an older policy schema, so it
is not used by the active v2 training run. See the English historical notes under `docs/archive/`.
